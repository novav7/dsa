Practical Content

Theory
Postfix is a Mail Transfer Agent that handles SMTP delivery. Dovecot provides mailbox access using IMAP and POP3.
A classroom deployment can demonstrate local mail flow without exposing the server as an Internet mail relay.
Procedure
1. Install Postfix and Dovecot packages.
2. Configure Postfix for the lab domain and local delivery.
3. Configure Dovecot mailbox location and protocols.
4. Restart services.
5. Create two local users and send a local test message.
6. Verify mailbox access with a mail client or protocol test.
Important Commands / Configuration
sudo apt-get install postfix dovecot-imapd dovecot-pop3d mailutils
# Important Postfix parameters (use postconf -e or edit main.cf carefully)
sudo postconf -e 'myhostname = mail.lab.example'
sudo postconf -e 'mydomain = lab.example'
sudo postconf -e 'myorigin = $mydomain'
sudo postconf -e 'inet_interfaces = all'
sudo postconf -e 'mydestination = $myhostname, localhost.$mydomain, localhost, $mydomain'
sudo postconf -e 'mynetworks = 127.0.0.0/8, 192.168.10.0/24'
sudo postconf -e 'home_mailbox = Maildir/'
# Dovecot: ensure protocols include imap pop3 and mail_location = maildir:~/Maildir
sudo systemctl restart postfix
sudo systemctl restart dovecot
sudo adduser mailuser1
sudo adduser mailuser2
echo 'Linux mail lab test' | mail -s 'Test' mailuser2@lab.example
sudo tail -n 40 /var/log/mail.log
Verification
1. Check Postfix and Dovecot service status.
2. Verify the message is delivered to the second local user.
3. Review /var/log/mail.log for delivery status.
Observations / Precautions

Do not configure an unrestricted SMTP relay.

Production Internet mail requires DNS/MX, TLS, anti-spam controls, reputation management, and other safeguards
beyond this practical.
Practical 15: NFS Server and Client Configuration
Aim
Configure an NFS export and mount it from a Linux client; understand Windows interoperability options.


Requirements
Ubuntu Server 16.04 LTS virtual machine or lab server, sudo-enabled administrator account, and a client VM where
required. Take a VM snapshot before changing network, firewall, authentication, disk, or directory-service settings.
Theory
NFS provides network file sharing primarily for Unix/Linux systems. The server defines exported directories in
/etc/exports. Modern Windows editions may support an NFS client feature, but availability depends on edition; Samba is
generally the standard choice for Windows-oriented sharing.
Procedure
1. Install NFS server packages.
2. Create an export directory and permissions.
3. Define the allowed client subnet.
4. Export the directory and restart NFS.
5. Install the NFS client package on Ubuntu client.
6. Mount and test read/write access.
Important Commands / Configuration
sudo apt-get install nfs-kernel-server
sudo mkdir -p /srv/nfs/share
sudo chown nobody:nogroup /srv/nfs/share
# /etc/exports
/srv/nfs/share 192.168.10.0/24(rw,sync,no_subtree_check)
sudo exportfs -ra
sudo exportfs -v
sudo systemctl restart nfs-kernel-server
# Ubuntu client
sudo apt-get install nfs-common
sudo mkdir -p /mnt/nfs
sudo mount 192.168.10.10:/srv/nfs/share /mnt/nfs
mount | grep nfs
touch /mnt/nfs/client-test.txt
Verification
1. Use exportfs -v on the server.
2. Verify the client mount.
3. Create/read a test file according to permissions.
Observations / Precautions

Avoid insecure broad exports such as *(rw) in real networks.

NFS identity/permission behavior should be planned carefully.
