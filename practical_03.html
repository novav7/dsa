Practical 3: Service Management and Boot Configuration
Aim
Inspect running services, enable/disable services at boot, stop unnecessary services, and analyze service logs.
Requirements
Ubuntu Server 16.04 LTS virtual machine or lab server, sudo-enabled administrator account, and a client VM where
required. Take a VM snapshot before changing network, firewall, authentication, disk, or directory-service settings.
Theory
Ubuntu 16.04 uses systemd for service and boot management. systemctl controls units, while journalctl displays systemd
journal records. Some packages may also retain traditional logs under /var/log.
Procedure
1. List active services.
2. Inspect a selected service status.
3. Enable a service at boot and then disable it.
4. Stop and start the service.
5. Read recent service logs and boot errors.
Important Commands / Configuration
systemctl --type=service --state=running
systemctl status ssh
sudo systemctl enable ssh
sudo systemctl disable ssh
sudo systemctl start ssh
sudo systemctl stop ssh
sudo systemctl restart ssh
journalctl -u ssh --no-pager -n 30
journalctl -p err -b --no-pager
systemctl list-unit-files --type=service
Verification
1. Use systemctl is-enabled ssh.
2. Use systemctl is-active ssh.
3. Review the last 20–30 journal entries for the service.
Observations / Precautions

Do not disable networking, SSH, or authentication services on a remote machine unless console recovery is available.
