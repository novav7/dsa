Practical Content

Theory
FTP is a traditional file-transfer protocol. Plain FTP does not encrypt credentials or data; it is suitable here only as a
syllabus exercise on an isolated lab. For real deployments, prefer SFTP or properly configured FTPS.
Procedure
1. Install vsftpd.
2. Back up the configuration.
3. Enable local users and uploads.
4. Restrict local users to their home directories.
5. Restart the service.
6. Test login, upload, and download from a client.
Important Commands / Configuration
sudo apt-get install vsftpd
sudo cp /etc/vsftpd.conf /etc/vsftpd.conf.bak
# Key settings in /etc/vsftpd.conf
local_enable=YES
write_enable=YES
chroot_local_user=YES
allow_writeable_chroot=YES
sudo systemctl restart vsftpd
sudo systemctl status vsftpd
ss -tlnp | grep :21
# Client test
ftp 192.168.10.10
Verification
1. Authenticate with a designated lab user.
2. Upload a non-sensitive test file and download it.
3. Confirm the user cannot browse outside the intended directory.
Observations / Precautions

Plain FTP exposes credentials; never use real passwords on untrusted networks.

Passive FTP may require additional firewall port configuration.
Practical 14: Mail Server Configuration (Postfix, POP3, IMAP)
Aim
Configure Postfix and Dovecot for basic local-network SMTP, POP3, and IMAP mail testing.
Requirements
Ubuntu Server 16.04 LTS virtual machine or lab server, sudo-enabled administrator account, and a client VM where
required. Take a VM snapshot before changing network, firewall, authentication, disk, or directory-service settings.
