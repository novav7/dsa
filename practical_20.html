Practical 20: Enterprise Linux Server Deployment and Service Integration
Aim
Design and validate an integrated Linux server infrastructure combining core network, identity, file, web, database,
remote-access, and firewall services.
Requirements
Ubuntu Server 16.04 LTS virtual machine or lab server, sudo-enabled administrator account, and a client VM where
required. Take a VM snapshot before changing network, firewall, authentication, disk, or directory-service settings.
Theory
Enterprise server deployment requires planning dependencies before installation. DNS and static addressing underpin
service discovery; DHCP can distribute network settings; identity services centralize users; NFS/Samba provide file
services; Apache/MySQL support applications; SSH provides administration; and the firewall restricts exposure.
For a classroom capstone, separate services across multiple VMs when resources permit. This reduces port/service
conflicts and makes troubleshooting clearer.
Procedure
1. Draw a topology and IP/service plan.
2. Assign static addresses to infrastructure servers.
3. Configure DNS first and verify forward/reverse resolution.
4. Configure DHCP with DNS information.
5. Deploy SSH and administrative access controls.
6. Deploy LDAP or NIS according to the exercise, then NFS/Samba.


7. Deploy Apache and MySQL.
8. Apply firewall rules based on required service ports.
9. Validate each service from Ubuntu and Windows clients.
10. Record evidence and troubleshooting notes.
Important Commands / Configuration
# Example validation checklist commands
ip addr

dig @192.168.10.10 www.lab.example
nslookup www.lab.example 192.168.10.10
ssh student1@192.168.10.10
showmount -e 192.168.10.10
smbclient -L //192.168.10.10 -U student1
curl -I http://site1.lab.example
mysql -u labuser -p college_db
sudo ufw status verbose
systemctl --failed
journalctl -p err -b --no-pager
Verification
1. Verify clients receive correct IP/DNS settings.
2. Verify DNS forward and reverse lookup.
3. Verify remote SSH login.
4. Verify file sharing from Linux and Windows as applicable.
5. Verify website and database access.
6. Verify only required firewall ports are reachable.
7. Check failed units and error logs.
Observations / Precautions

Do not expose this multi-service teaching server directly to the Internet.

Use snapshots and document configuration dependencies.

For assessment, include topology, IP table, service table, screenshots/output, test cases, and conclusion.
