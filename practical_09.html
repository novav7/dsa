Practical 9: DNS Server Installation and Configuration (BIND9)
Aim
Install BIND9, configure forward and reverse lookup zones, test resolution, and restrict queries to the lab network.
Requirements
Ubuntu Server 16.04 LTS virtual machine or lab server, sudo-enabled administrator account, and a client VM where
required. Take a VM snapshot before changing network, firewall, authentication, disk, or directory-service settings.
Theory
BIND9 is a DNS server implementation. Forward zones map names to IP addresses, while reverse zones map IP
addresses to names using PTR records. named-checkconf and named-checkzone help detect configuration errors before
restart.
Procedure
1. Install bind9 and dnsutils.
2. Define an ACL for the lab network.
3. Create forward zone lab.example.
4. Create reverse zone 10.168.192.in-addr.arpa.
5. Validate configuration.
6. Restart BIND and query records.
Important Commands / Configuration
sudo apt-get install bind9 dnsutils
# /etc/bind/named.conf.options (inside options, adapt carefully)
allow-query { 127.0.0.1; 192.168.10.0/24; };
# /etc/bind/named.conf.local
zone "lab.example" {
type master;
file "/etc/bind/db.lab.example";
};
zone "10.168.192.in-addr.arpa" {
type master;
file "/etc/bind/db.192.168.10";
};
# Forward zone essentials
$TTL 86400
@ IN SOA ns1.lab.example. admin.lab.example. ( 1 3600 1800 604800 86400 )
@ IN NS ns1.lab.example.
ns1 IN A 192.168.10.10
www IN A 192.168.10.20
# Reverse zone essentials
$TTL 86400
@ IN SOA ns1.lab.example. admin.lab.example. ( 1 3600 1800 604800 86400 )
@ IN NS ns1.lab.example.
10 IN PTR ns1.lab.example.
20 IN PTR www.lab.example.
sudo named-checkconf
