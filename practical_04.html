Practical 4: Linux Firewall Configuration using UFW and iptables
Aim
Configure host-based firewall rules with UFW and iptables for SSH, HTTP, DNS, and selected source networks.
Requirements
Ubuntu Server 16.04 LTS virtual machine or lab server, sudo-enabled administrator account, and a client VM where
required. Take a VM snapshot before changing network, firewall, authentication, disk, or directory-service settings.
Theory
UFW is a simplified firewall management interface commonly used on Ubuntu. iptables exposes lower-level Netfilter
rule management. Firewall changes should be applied carefully, especially over SSH, to avoid locking out the
administrator.
Procedure
1. Inspect existing firewall state.
2. Allow SSH before enabling UFW.
3. Allow HTTP and DNS as required.
4. Restrict SSH to the lab subnet.
5. Inspect equivalent iptables rules.
6. Demonstrate a temporary deny rule and remove it.
Important Commands / Configuration
sudo ufw status verbose
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 53/tcp
sudo ufw allow 53/udp
sudo ufw allow from 192.168.10.0/24 to any port 22 proto tcp
sudo ufw enable
sudo ufw status numbered
sudo iptables -L -n -v
sudo iptables -A INPUT -s 192.168.10.50 -p tcp --dport 80 -j DROP
sudo iptables -L INPUT -n --line-numbers
# Remove the exact temporary rule
sudo iptables -D INPUT -s 192.168.10.50 -p tcp --dport 80 -j DROP
Verification
1. From an allowed client, test SSH and HTTP.
2. Use sudo ufw status numbered to confirm rules.
3. Verify the temporary iptables rule is removed after testing.
Observations / Precautions

Always allow the management path before enabling a default-deny firewall.

iptables persistence requires additional configuration/package; do not assume runtime rules survive reboot.
