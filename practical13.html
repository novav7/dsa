# Practical No.: 3

Aim: Process Priority and Scheduling.

Theory: Every process has a scheduling priority defined by a “Nice Value” ranging from -20 (highest priority) to 19 (lowest priority). Standard user tasks default to a value of 0.

Requirements:

- Linux
- WSL Terminal

a] Check process priority using `top`

`$ top` – In the dashboard, the NI column lists the nice value and the column indicates the process's actual scheduling priority.

b] Start process with priority using `nice`

`$ nice -n 10 top` – Launches a new command with a custom nice value added to the default.

c] Change priority using `renice`

`$ renice -n 5 -p 1234` – Dynamic adjustment command running prior using target PID.

d] Observe impact of priority on CPU usage

Highly priority task allocated large reading execution time than lower priority to fostered.
